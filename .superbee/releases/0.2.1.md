# Superbee 0.2.1

Superbee 0.2.1 enforces OKF v0.2 authoring rules on v0.2 bundles, adds document verification with trust tiers and explicit frontmatter field actions, and clarifies first-time sharing and managed reader recovery.

This release was published on 2026-09-14 as `superbee@0.2.1` under
the npm `latest` tag.

# What changed

- Writes to an OKF v0.2 bundle require an OKF actor spelling: human:id, process:id, or producer/version such as openai/codex. Other spellings, including role-qualified paths such as openai/codex/root, are refused with a suggested correction. home and session-start show the resolved actor and flag one that would be refused. OKF v0.1 bundles keep their previous actor handling.
- On a v0.2 bundle, a meaningful content change records the resolved actor in generated.by, falling back to process:superbee only when no actor is known. Verification does not change generated.by or generated.at.
- doc verify appends an OKF v0.2 verified event naming the actor as verifier. The derived trust tier (unverified, machine-confirmed, or human-reviewed) appears in the verify receipt, status, list --fields trust, home, and the local document reader.
- doc field adds explicit frontmatter actions: set for supported single-value fields, add and remove for tags and sources, edit for one source, and version-guarded replace-all for a complete tags or sources list. doc update no longer accepts --tag, refuses to replace list values implicitly, and rejects a repeated field flag.
- Authored OKF v0.2 standard fields are validated before a write, independently of Kind strictness. Newly authored timestamps need a date, time, and explicit UTC offset; lifecycle status must be draft, stable, or deprecated; sources, verified, and tags must have their standard shapes. Unchanged imported values are preserved.
- doc write, doc update, and new accept --stale-after with an explicit instant. status reports existing date-only or malformed stale_after values as invalid_stale_after without rewriting them.
- status and Kind discovery warn with OKF_WORKFLOW_STATUS_COLLISION when a v0.2 Kind declares workflow values in top-level status. Move that workflow state to superbee_progress_status and keep using the logical progress_status field.
- First-time sharing distinguishes an unverifiable remote, an existing repository without a board branch, and an existing board branch. Failed create or update operations report structured details.sharing guidance and whether local work was preserved or committed. Superbee still does not create the remote repository.
- In a fresh clone whose committed binding names the conventional .superbee path and whose origin/board exists, plain sync now provisions the shared board instead of recommending a replacement bundle.
- ui --stop --abandon releases a managed reader record whose listener cannot be proven live, without signaling the recorded process. A listener that proves it belongs to something else is now treated as absent automatically, and ui --status rows include the process ID.

# What you need to do

Upgrade with npm install -g superbee, verify superbee version against the linked evidence, and rerun superbee setup for your host, applying any returned action and restarting when instructed. On OKF v0.2 bundles, update scripts and agent instructions that pass a non-conforming --actor or SUPERBEE_ACTOR value, replace doc update --tag with doc field, and run superbee status to review trust counts, invalid timestamp findings, and any workflow status collision before relying on affected Kinds.

# Compatibility

Node.js 20 or newer is required. macOS, Linux, and Windows remain supported. The setup selectors remain codex, claude-code, claude-desktop, and opencode. No stable 0.2.0 was published; 0.2.1 follows 0.1.6 on the latest tag. New bundles continue to use OKF v0.2 and existing v0.1 bundles remain supported without automatic migration. The stricter authoring rules apply only to v0.2 bundles and only to newly supplied or changed values. Stable behavior is tied to v0.2.1; later main-branch and prerelease changes are outside this release.

# Recovery

Preserve or commit bundle work before upgrading. If a write is refused, read the returned message and help: they name the corrected actor spelling, field action, or timestamp form, and no bytes were written. To restore the prior documented CLI, run npm install -g superbee@0.1.6 and verify its version; 0.1.6 reads the same bundle editions and preserves verified and stale_after values, but it does not report trust tiers or enforce the 0.2.1 authoring checks. Stop a managed reader with the same bundle and actor used to launch it before replacing its CLI installation.
